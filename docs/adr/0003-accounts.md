# 0003: Аккаунты Discord/Telegram и PostgreSQL

Статус: принято, 2026-11-11.

## Контекст

Нужен вход через Discord и Telegram с ником и аватаром, гостевая игра остаётся. Пользователь не хочет входить каждый раз и просит хорошую защиту базы. Телефоны и другие лишние данные не собираются.

## Решение

- Хранилище за интерфейсом `AccountStore` (`auth/store.js`): PostgreSQL в проде, память в разработке и тестах. Драйвер `pg` загружается только при `DATABASE_URL`, поэтому гостевая игра по-прежнему стартует без зависимостей.
- Храним минимум: имя, @username, аватар (байты, до 128 КБ), `provider_key = HMAC-SHA256(AUTH_SECRET, provider:id)`. Сам id провайдера, токены, телефон и почта не хранятся. Утёкшая база без секрета не сопоставляется с аккаунтами.
- Сессия: 32 случайных байта в cookie `alias_session` (HttpOnly, SameSite=Lax, Secure), 30 дней со скользящим продлением, в базе — SHA-256.
- Discord: code + PKCE + state, scope `identify`; токен отзывается сразу после чтения профиля. Telegram: Login Widget с проверкой HMAC, свежесть 5 минут, защита от повтора.
- Аватары скачивает сервер с разрешённых https-хостов с проверкой сигнатуры картинки и отдаёт с `/avatars/<id>`.
- Две роли БД: `alias_migrator` (DDL) и `alias_app` (только DML). Миграции — `npm run migrate`.
- Аккаунт привязан к игроку; модель «игрок ≠ устройство» сохранена.

## Последствия

Появилась одна зависимость и служба PostgreSQL на сервере, нужны резервные копии. Живой вход требует HTTPS-домена (задача 27). Для граждан РФ база должна быть в России; уведомление РКН подаёт владелец.
