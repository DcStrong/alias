## Следующие безопасные действия

1. Проверить лимиты и продолжать только при запасе >10% обоих применимых окон; не применять кредиты/сбросы без запроса.
2. Прочитать AGENTS.md, map.md, задачи 08/09 и deploy/README.md. Проверить git status и origin/main, сохранить чужие изменения. Никаких изменений сложного словаря.
3. Просканировать отправляемые файлы/историю на секреты без вывода значений; зафиксировать актуальные документы и обычным push отправить main, без force. Записать итоговый SHA.
4. Проверить SSH, current release, alias/nginx/renewal timer и HTTPS. Подготовить архив только runtime из итогового commit (git archive), без .git, credential, локальных конфигов.
5. Распаковать в новый /opt/alias/releases/<commit>, записать REVISION, выполнить node --check, сохранить старый target current для отката. Атомарно переключить current, restart alias, дождаться HTTP readiness. Если startup не проходит — вернуть previous current и restart alias до остановки работы.
6. Не менять Nginx/TLS/UFW/SSH без обнаруженной необходимости. Не запускать provision.sh. При рестарте комнаты пропадут; пользователь об этом предупреждён.
7. Компактно проверить basic/hard через два API/SSE клиента: setting сохраняется/виден всем, текущая карточка только объясняющему, reconnect сохраняет её; HTTPS доверенный, без отключения проверки сертификата. Полные автоматические игровые циклы уже покрыты 23 локальными тестами.
8. Сверить runtime SHA256 с commit, записать публичные результаты, deployed SHA/release и окончательные статусы, при необходимости отправить итоговые evidence docs обычным push. Удалить временные credential/helpers и очистить память секрета. Проверить лимит и вернуть фактический итог.
