## Критерии приёмки

- [x] Объясняющий может один раз зачесть именно сохранённую неразыгранную карточку после таймера; паре/команде +1, в каждый за себя объясняющему и выбранному угадавшему по +1.

### Контракт для задач 17/18

- POST `/api/rooms/:code/action`, JSON `{type:"awardLast", version, card, winner?}`. Только устройство сохранённого объясняющего, фазы `summary`/`finished`, только незачтённая карточка после истечения таймера. `winner` обязателен в ffa: существующий, не выбывший игрок, отличный от сохранённого объясняющего. Общая версия комнаты и сохранённый ID проверяются до начисления; действие синхронно/атомарно. Никаких новой карточки или таймера.
- `lastCard` приватен устройству объясняющего и содержит `{id,word,result,claimable,explainer}`; внутренний снимок также хранит `device,team`. Публичный `pendingLast` сообщает только о незакрытом праве зачёта. После зачёта `result:"guess"`, `claimable:false`; публичные `history` и `lastCompleted` раскрывают угаданное слово и обновлённый счёт через SSE.
- `next` с последующим реальным ходом и `restart` отклоняются при pending без `discardLast:true`. Этот флаг явно и атомарно закрывает право вместе с переходом. `next` после последнего запланированного живого игрока допускается без флага и переносит pending в `finished`; сохранённый `explainer` используется вместо уже отсутствующего `active`.
- Для задачи 17 поздняя FFA-кнопка пока двухшаговая: `guesserButtons(players,lastCard.explainer,selectedWinner)` и `#award-last`. Обработчик захватывает `lastCard.id` при отрисовке; `act` уже имеет блокировку busy. Имя должно отправлять тот же `awardLast` с captured ID и выбранным winner.
- Для задачи 18 сбрасывать `room.lastCard` вместе с `lastCompleted`, `history`, таймером/колодой/счётом. Отдельной переменной pending нет: `pendingLast` вычисляется из `lastCard.claimable`.
