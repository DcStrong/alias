# 18: Завершить игру и вернуться в лобби той же комнаты

Status: готово-для-агента
Progress: в работе — реализация и автоматические проверки готовы, финальная проверка после merge

**What to build:** ведущий завершает текущую партию без выхода участников и возвращает ту же компанию в настройки комнаты.

**Blocked by:** 13, 16.

- [ ] Отдельная команда только ведущему из handoff/playing/summary/finished; code/devices/players/команды/порядок/настройки сохраняются.
- [ ] Таймер, расписание, колода, очки, история и любые поздние/pending карточки очищаются; готовность сбрасывается, клиенты синхронизируются.
- [ ] Повтор/гонка со старой карточкой или таймером не затрагивает новую партию; в лобби действие безопасно идемпотентно.
- [ ] Можно изменить настройки и снова стартовать в той же комнате.
- [ ] В UI «Завершить игру» отличается от «Выйти» и кратко подтверждает потерю результатов.
- [ ] Содержательные HTTP/SSE тесты проверяют сохранение компании, авторизацию, остановку таймера и повторный старт.

2026-11-03: TDD на согласованной HTTP/SSE границе: сначала красный тест отсутствующей команды, затем реализация; отдельный красный сценарий выявил сохранение выбывших игроков, после исправления зелёный. Добавлены шесть содержательных тестов: права ведущего, все четыре фазы, сохранение комнаты/устройств/настроек/команд/порядка, повтор в лобби, сброс готовности и результатов, новый старт, уход и отключение участников, старые запросы, таймер и гонки guess/awardLast. `npm run check`, `git diff --check`, полный `npm test` — 46/46 до merge актуальной integration. Изменение кнопки и короткий confirm проверяются пользователем при ручной приёмке; агент браузер не запускал. Без push/deploy.

Контракт: POST `/api/rooms/:code/action`, JSON `{type:"endGame",version}`. Только ведущий; handoff/playing/summary/finished → lobby, lobby → безопасный повтор без сброса уже выставленной готовности. Общая проверка версии предшествует действию; старые endGame/card/awardLast не меняют новую партию. Явная команда завершения закрывает pending без отдельного discardLast; UI подтверждает потерю результатов и незачтённого последнего слова. Общий resetGame также используется restart с сохранением прежнего требования discardLast для pending.

Сохраняется весь невыбывший состав, включая отключённых игроков, ID устройств, команды и относительный порядок. Явно вышедшие tombstones удаляются как при restart, чтобы новый старт не создавал их призрачных ходов. Следующий шаг: merge актуальной integration, повтор проверок и передача merger.
